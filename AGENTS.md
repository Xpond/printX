# PrintShop Tools handoff

- Spec: `docs/PLAN.md`. Keep changes simple, files around 200 lines or less, and UI copy in `ui/text.py`. Use `rb` before rediscovering code.
- Develop on Linux; target Windows 10/11 x64. The Windows 11 VM has 2 GB RAM. Never require copying ZIPs or using a shared VM folder: deliver an installer `.exe` through GitHub Releases. The repository is public, so downloads need no login.
- Phase 1 complete: PySide6 home/tool screens, settings, logs, background jobs with cancellation, lazy thumbnails, and Make PDF for images/PDFs. Supports ordering, lossless JPEG embedding, multi-page TIFF, passwords, corrupt-file skipping, and safe output names.
- Post-phase-1 UI, from owner feedback (overrides PLAN.md's big drop zone and big buttons): compact, uncluttered layouts with no filler space. Tool titles sit in the window header. Make PDF has no drop zone: its grid of 128 px thumbnails (two-line names, drag to reorder) takes drops and opens the file picker when clicked empty. Options are two aligned rows with an editable File name for the combined PDF.
- Phase 2 complete (owner OK, released as v0.2.0): Upscale image. Fit print size (A6–A0, photo sizes, Letter/Legal/Tabloid, custom) at 300/150 DPI, or 2×/3×/4×. Tiles show pixel size, the print size the original is sharp at, and a badge: up to 2× green, up to 4× amber, beyond red. Lanczos in 256-row strips (one full-size buffer) plus an unsharp mask with a small radius (min(0.6 + 0.1 × scale, 1.2)); Light 70% and Strong 140% were tuned on real crops for no halos. Premultiplied alpha, Hard edges = nearest neighbour at a whole-number scale, CMYK/ICC/transparency kept, DPI written, JPEG q95 4:4:4, TIFF LZW, HEIC/WEBP saved as JPG (PNG when transparent). Benchmark: threads matched processes, so files run in worker threads within a 512 MB budget.
- Phase 3 in progress. Compress PDF and Split PDF released as v0.3.0, awaiting the owner's VM checks and OK; Organize pages and PDF to images remain. Compress: Ghostscript 10.08 pdfwrite runs inside the worker via its C API (ctypes), so Cancel's worker kill also stops it. Windows Ghostscript cannot open paths with emoji, so it only gets plain names inside the staging folder (a hard link to the original, or a copy on another drive) with that folder as its working directory; Windows bundles the pinned, checksummed `gsdll64.dll` (AGPL, like PyMuPDF) fetched by `scripts/ghostscript.py` into `vendor/`, and Linux uses the system libgs. Levels: Smallest = /ebook at 100 DPI (72 DPI blurred scanned text), Recommended = /ebook at 150 DPI, Print = /printer at 300 DPI. All keep colours unchanged (CMYK, spot colours and grey scans survive; sRGB conversion was 18× slower on grey scans) and never auto-rotate pages. PyMuPDF's `rewrite_images` corrupted CMYK and grey images, so it is not used. A result must have every page and be smaller, otherwise the original is kept as "Already optimized". Forms are flattened and passwords are not kept on the copy.
- Split PDF: every page, page ranges (`1-3, 5, 8-10`, one PDF per range; any page past the end skips that file) or every N pages, into a new `name_split` folder that is finished in staging and then renamed into place, so cancelling never leaves half a folder. Page numbers are zero-padded (`_page_01`) so RIPs and hot folders sort parts in page order. Compress and Split share the per-file job loop `each_file` in `core/files.py`.
- AI tools (owner request; v0.4.0 released, 0.4.1 fixes the owner's first VM feedback, awaiting their checks and OK): an AI row tops the home screen (process-yellow accent, sparkle icons, "AI" tag, also in the window header); Logo to vector is dropped. Both use OpenRouter's `/api/v1/images` endpoint (`core/openrouter.py`, stdlib urllib; references are `{"type": "image_url", "image_url": {"url": data-URL}}`, answers are `data[].b64_json`). Settings take an API key that is never shown (DPAPI-sealed on Windows, `core/secret.py`) and one model name per tool (empty = default, so new defaults still apply). `ui/ai_tool.py` holds what both screens share: key gating, the key hint, a busy bar.
- Remove background: Ming (free) answers ~1 MP layers aligned with the input, always the cut-out first and the filled-in base last, and needs a layer plan in the prompt ("Number of layers: 2. Layer 1: X, with a transparent background. Layer 2: …"; a plain "Remove the background" returns the photo unchanged). Background mode puts its alpha on the full-size original (transparent PNG); Something else pastes only the areas Ming changed (blurred difference > 8, widened and feathered) onto the original, so results keep full resolution. `resolution` is ignored.
- Enhance image: a chat about one photo (`ui/chat.py`); the hidden file list holds the highlighted version, so the shared job flow sends it with the instruction plus "Keep everything else exactly as it is." Muse ($0.01, 13–24 s) answers ~2.4 MP WEBP whatever the input or `resolution`, keeping the whole frame but stretching it up to ~3% onto its size grid; the job undoes stretches under 6% and saves each version as `original_enhanced` in the original's format. Results smaller than a large original are a known limit.
- Owner feedback on 0.4.0: a saved key looked unsaved because the write-only box empties, and the AI screens had a huge photo area beside tiny one-line prompts. 0.4.1: the empty key box's placeholder says whether a key is saved, "Settings saved" shows beside the button, and `app.py` logs uncaught UI errors to app.log (a windowed build otherwise swallows them). Remove background keeps batches but shows them in one fixed row; descriptions and Enhance's composer use `Prompt` (`ui/ai_tool.py`, multi-line, Enter runs, Shift+Enter new line), which takes Remove's spare height and a quarter of Enhance's; Enhance's empty state is a photo-sized dashed card. A Windows-only test saves the key through the registry, as the installed app does.
- Shared job flow lives in `ui/tool_screen.py`; each tool passes its copy dict (`T.MAKE`, `T.UPSCALE`, `T.COMPRESS`, `T.SPLIT`) and options. Known: at the 680 px minimum width tool pages scroll sideways (Make PDF's rows already need about 740 px), and tiles say "1 pages" for one-page PDFs.
- Verified: 49 tests pass on Linux and Windows; the source, packaged and installed smoke tests run Make PDF, Upscale, Compress and Split and screenshot the AI screens. AI jobs were run live against OpenRouter from source on Linux. Reviewed light/dark screenshots, including the native Windows ones from CI. Last measured first frame: 1.19 seconds packaged, 0.64 installed. The installer is 75.0 MB (Ghostscript added about 12 MB). Samples and manual checks are in `samples/`, `docs/PHASE1-TESTING.md` to `docs/PHASE3-TESTING.md`, and `docs/AI-TESTING.md`.
- Packaging: pinned Python 3.14 dependencies, a PyInstaller one-folder build inside an Inno Setup installer, and Windows CI. Never force `QT_QPA_PLATFORMTHEME=generic` on native Windows.
- Releases: the feature PR bumps the version in `installer.iss`, `assets/windows.manifest` and `RELEASE-NOTES.md`, and points `scripts/build_installer.py` at the phase checklist (installed as Read me first). Windows CI runs on main after merge and on tags; never start it on a branch. Once the main build is green, tag `vX.Y.Z` on main to publish.
- After each phase: test, launch, review `QWidget.grab()` screenshots, give exact manual checks, commit, and wait for the owner's OK.
